Guía de Conexión API REST

Paso a paso para reenviar y validar firmas digitales desde el sistema de tu empresa hacia HSM Sign CR.

¿Cómo funciona la integración?

Cuando un cliente o usuario ingresa su Identificación y PIN de Firma en el sistema de tu empresa, tu servidor debe reenviar esos datos a nuestra API. Nosotros verificamos si el usuario existe en nuestro HSM, validamos su clave criptográfica y le devolvemos a tu sistema la respuesta inmediata (Confirmado / Usuario no existe / PIN incorrecto).

Paso 0: Dirección Base y Encabezados

Toda comunicación se realiza mediante peticiones HTTP tipo POST. Debes asegurarte de enviar siempre el encabezado Content-Type: application/json.

Endpoint de Validación y Firma

URL: https://api.hsmsign.cr/v1/validar-firma
Método: POST
Formato de datos: JSON

Paso 1: El JSON que debes enviar (Body Request)

Este es el archivo JSON exacto que tu sistema debe construir y enviar al endpoint cuando el usuario solicita firmar o validar: 

{
  "cedulaUsuario": "118230456",
  "pinFirma": "ClaveSegura123!",
  "idDocumento": "FAC-2026-0089"
}

• cedulaUsuario: Identificación del cliente que firmará el documento.
• pinFirma: La contraseña/PIN que el usuario digitó en tu formulario.
• idDocumento: El identificador único del documento o transacción en tu sistema.

Paso 2: Código JavaScript para copiar y pegar (Fetch)

Si estás desarrollando tu proyecto en JavaScript (Node.js o Frontend), puedes usar esta función para enviar la solicitud a nuestra API: 

// Función para reenviar la firma a la API de HSM Sign CR
async function enviarFirmaAHsm(cedula, pin, idDoc) {
  const url = 'https://api.hsmsign.cr/v1/validar-firma';
  
  const datos = {
    cedulaUsuario: cedula,
    pinFirma: pin,
    idDocumento: idDoc
  };

  try {
    const respuesta = await fetch(url, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(datos)
    });

    const resultado = await respuesta.json();
    procesarRespuesta(resultado);

  } catch (error) {
    console.error('Error de conexión con el API:', error);
  }
}

Paso 3: Respuestas que recibirá tu sistema

Dependiendo de si el usuario existe o no en nuestro sistema HSM, el API te devolverá uno de los siguientes JSON:

✔ CASO 1: El usuario existe y el PIN es correcto (HTTP 200 OK) 

{
  "exito": true,
  "estado": "USUARIO_VALIDADO",
  "mensaje": "Firma procesada con éxito",
  "firmaDigital": "a8f9c2d1e0b3...[Hash Criptográfico]",
  "fechaRegistro": "2026-08-19T14:30:00Z"
}

✖ CASO 2: El usuario NO existe en HSM Sign CR (HTTP 404 Not Found) 

{
  "exito": false,
  "codigoError": "USUARIO_NO_ENCONTRADO",
  "mensaje": "La cédula ingresada no posee un certificado digital en HSM Sign CR"
}

⚠ CASO 3: PIN incorrecto o cuenta bloqueada (HTTP 401 Unauthorized) 

{
  "exito": false,
  "codigoError": "PIN_INCORRECTO",
  "intentosRestantes": 2,
  "mensaje": "El PIN de firma digitado no coincide"
}

Paso 4: Mostrar el resultado en la pantalla de tu proyecto

Una vez que tu código recibe la respuesta del API, debes actuar según el valor del campo exito:

Flujo sugerido para la interfaz de tu empresa

• Si exito === true: Muestra un mensaje verde "Documento firmado exitosamente", guarda el Hash recibido y permite completar la transacción.
• Si codigoError === "USUARIO_NO_ENCONTRADO": Muestra una alerta indicando al cliente que debe registrarse previamente en la plataforma de HSM Sign CR antes de poder firmar.
• Si codigoError === "PIN_INCORRECTO": Informa al usuario cuántos intentos le quedan antes de que el sistema bloquee temporalmente sus firmas (3 intentos máximo).
